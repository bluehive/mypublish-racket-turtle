# Antigravity 高校生向けわかりやすさレビュー

## 総合評価（噛み砕けている度: B+）
**一言評価**: Scratch 経験のある高校生目線に寄り添った非常に丁寧で分かりやすい構成。ただし、付録や発展コラムで大学生・開発者レベルの専門用語や概念の跳躍が見られるため、あと一歩の噛み砕きで完璧になります。

## よくできている点
- **Scratch と Racket の架け橋**: `intro.md` や `ch01-basics.md` で、Scratch のブロックと Racket の括弧 `()`（「括弧はブロックの枠線」）やリストの対応を直感的に例えており、文法への恐怖心を払拭できている。
- **直感的な比喩とステップ設計**: `ch03-recursion.md` のマトリョーシカ人形による「再帰」の説明や、基底条件・再帰ステップの2ルールの整理が非常に明快。
- **テンプレート（型紙）による再現性**: `ch04-fractals.md` でフラクタル描画の共通テンプレートを提示し、ツリー・コッホ・シェルピンスキー・ドラゴン曲線を比較・応用しやすく構成されている。
- **状態（向き・位置）の解説**: `ch04-fractals.md` で「なぜ `forward (- size)` で戻る必要があるのか」をカメの内部状態（向き・位置）と関連付けて説明しており、よくあるバグの原因を先回りして解消している。

## 段差・わかりにくさ（ファイル別・重要度高/中/低）

### intro.md
- **中** / 0.3 学びのレベル分け表 (L98) / 「`#lang racket` + `plot` | データや数式の宣言的プロット・Headless 画像出力」 / 「データや数式をそのままグラフにするプロット・画面を出さずに画像ファイルとして保存する機能」 / 「Headless」や「宣言的」は Web 開発や言語論の専門用語であり、高校生には未定義で理解の妨げになるため。
- **低** / 0.3 REPL の説明 (L105) / 「相互作用ウィンドウ（REPL: Read-Eval-Print Loop）」 / 「相互作用ウィンドウ（REPL：1行ずつ試せる実験場）」とし、英語略称の補足は最小限にする / REPL という英略称が唐突で身構えてしまうため。

### ch01-basics.md
- **高** / 1.1 前置記法 (L35) / 「前置記法（ポーランド記法）」 / 節見出しを「前置記法（記号を一番最初に書く書き方）」とし、本文中で「学術的にはポーランド記法とも呼ばれます」と補足する / 「ポーランド記法」という固い漢語が序盤に出ると難解な印象を与えるため。
- **中** / 1.3 述語（Predicate）(L101) / 「真偽値（`#true` または `#false`）を返す関数のことを、プログラミングでは **述語（Predicate）** と呼びます。」 / 「YES/NO（`#true` か `#false`）で答える質問のような関数を、プログラミング用語で**述語（Predicate）**と呼びます」 / 国語や数学の「述語」の概念と混同しやすいため、役割（質問する関数）を例示したい。
- **中** / 1.4 リストの再帰チラ見せ (L180-L184) / `my-length` のコードのみ / コードの直後に「例えば `(my-length (list "a" "b"))` なら `1 + (my-length (list "b"))` → `1 + 1 + 0 = 2` と小さくなっていく」という計算の追跡例を2行添える / 式 `xs` と `rest` だけでは具体的にどう動くかイメージしにくいため。

### ch02-turtle.md
- **高** / 2.0 手続き型とデータ駆動 (L21-L25) / 「これを **手続き型（Procedural）** の描画…」「考え方を **データ駆動（Data-Driven）** と呼びます。」 / 「直接カメを動かす方式」と「まず『命令のメモ（指示書リスト）』を作ってから一気に動かす方式」と説明してからカッコ内で用語に触れる / 抽象的な専門用語が章の冒頭に出ると主題が見えにくくなるため。
- **中** / 2.0 歴史コラム (L19) / 「自分の体の感覚（ボディ・シントニック：身体を介した同型的な学び）を使って…」 / 「ボディ・シントニック」等の学術用語を外し、「『自分がカメになったつもりで歩いてみる』という身体の感覚を使って…」と噛み砕く / 論文調の専門用語は読者対象（高校生）にそぐわないため。

### ch03-recursion.md
- **中** / 3.2 テンプレートの分類 (L90, L110) / 「自然数（深さ・カウントダウン）の再帰」「リストの構造的再帰」 / 「数をカウントダウンする再帰（回数や深さ）」「リストを先頭から削っていく再帰」の見出しにする / 「構造的再帰」などの HtDP 用語が固く難解に聞こえるため。
- **低** / 3.2 階乗の例 (L100-L108) / 「階乗（Factorial: $n!$）の例」 / 数式 `5! = 5 × 4 × 3 × 2 × 1 = 120` のような具体的な計算例を1行入れる / 数式記号 $n!$ に馴染みのない高校生が立ち止まるのを防ぐため。

### ch04-fractals.md
- **高** / 4.3 シェルピンスキーの三角形 (L118-L144) / `sierpinski` 関数内で未定義の `triangle-outline` が突然登場し、後に説明される / `sierpinski` のコードを提示する前に `triangle-outline`（正三角形を描く最小パーツ）を定義・解説しておく / コード中に未定義の関数が出ると読者が混乱するため。
- **高** / 4.3 コラム `go-to` の座標系 (L146-L159) / 「`(go-to x y)` … カメを座標 (x, y) へ移動」 / 画面の原点 (0,0) がどこ（画面中央など）で、x軸・y軸の正の向きがどちらかを注記する / Scratch（中央原点）と一般的な画像ライブラリ（左上原点）で座標軸の仕様が異なるため、明記しないと移動位置が予想できない。
- **中** / 4.4 Plot コラム (L186-L210) / 「第一級オブジェクト」「関数型レンダラーの自由な重ね合わせ（Composability）」「Headless 自動生成」 / 開発者向けの宣伝調の用語を避け、「グラフを重ねて描ける」「画面を出さずに画像保存できる」などの平易な表現にする / 読者対象から外れたエンジニア向けマーケティング用語になっているため。

### closing.md
- **中** / 終.2 次の一歩 (L33-L38) / 「タートル描画: 手続き型・手順 / Plot 描画: 宣言型・関数型」 / 「タートル:『前進して曲がる』という手順を指示する描き方 / Plot:『この数式を描いて』と形を指定する描き方」と言い換える / 「宣言型（Declarative）」などの言語論用語は高校生には抽象的すぎるため。

### appendix-f-plot.md
- **高** / F.1〜F.2 全体 (L9-L30) / R言語との比較や「第一級オブジェクト」「Headless」などの開発者向け解説文 / 冒頭に「※プログラミングやデータサイエンスに興味がある人向けの発展付録です」と明記し、専門用語に高校生向けの注釈を入れる / 本編（Scratch経験者向け）との文体のギャップが非常に大きく、難解に感じられるため。
