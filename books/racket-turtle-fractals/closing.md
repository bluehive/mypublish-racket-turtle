> **この章のゴール**  
> 第1–3章で触れた「くり返し」を、手続きのくり返しから畳み込み・高階関数の見通しへつなぎ、グラフィックスでも関数の合成が実験の道具になることを確認する。  
> **想定読者**: プログラミングを楽しみたい人  
> **言語の流れ**: 第1–2章 BSL → 第3章 ISL（`build-list` / `map` / `foldr`）

---

#### 終.1 これまでの道のり（短く）

- **第1章** … 式・関数・リストなど、BSL の基本  
- **第2章** … タートルで進む・曲がる。`(repeat k …)` で同じ動きをそのまま回数分つなぐ  
- **第3章** … ISL に切り替え、`build-list` / `map` / `foldr` で **変化する** 命令列をまとめて作る  

ここまでで描けるようになったのは、正方形や正多角形だけでなく、長さが伸びる螺旋や、色を変えながら同じ型紙を並べる図などです。終章では、「ただ回数を回した」だけではなく、その裏で何が便利だったかを言葉にしておきます。

---

#### 終.2 手続きのくり返しから、畳み込みのくり返しへ

##### 同じことを何度も書く／そのままコピーする

いちばん素朴なくり返しは、命令を手で並べることです。

```racket
(list (forward 40) (turn-left 90)
      (forward 40) (turn-left 90)
      (forward 40) (turn-left 90)
      (forward 40) (turn-left 90))
```

第2章の `(repeat 4 …)` は、この「同じかたまりを回数分つなぐ」を短く書いたものです。これは **手続きのくり返し**——やる内容が決まっていて、回数だけ変える——に向きます。

##### 回ごとに中身が変わるとき

螺旋では、歩番号 `i` ごとに進む長さが変わります。同じリストをコピーするだけでは足りず、「i 番目の小さな命令リスト」を規則から生成する必要があります。そこで出てきたのが、

```racket
(foldr append empty (build-list n growing-step))
```

という型紙でした。

- `build-list` … 0 … n-1 のそれぞれに、名前付き関数を当ててリストを作る  
- 結果が二重リストなら `foldr append empty` で **1 本の CommandList に畳み込む**  

ここでいう「畳み込み」は、たくさんの小さなかたまりを、のり（`append`）と出発点（`empty`）で **1 つの結果にまとめる** くり返しです。単に「同じ文を n 回実行する」のではなく、**途中の部品を結合しながら全体を組み立てる** くり返し、と捉えると第3章のコードが読みやすくなります。

---

#### 終.3 高階関数の便利さ——「枠」と「1 回分」を分ける

`build-list` や `map` は、**別の関数を引数に取る** 関数でした。これを高階関数と呼びます。

高階関数の面白さは、「単なる回数のくり返し」を超えて、次のように書けるところにあります。

1. **くり返しの枠は共通** … 何個やるか、どのリストの上を走るかは `build-list` / `map` が担当する  
2. **1 回分だけを名前付き関数に書く** … 長さの式、色の付け方、ずらし方など、「変わるところ」だけを `define` する  
3. **必要なら畳み込んで全体にする** … 命令のかたまりが入れ子なら `foldr append empty`  

つまり、プログラムの「状態」や「変化の規則」を、巨大なコピペの列として持つのではなく、**小さな関数として切り出して渡す** ことができます。タートルで言えば、「進む長さ」「曲がる角度」「ペンの色」といった **描画のパラメータを、関数の引数や本体の式でシンプルに記述できる** のが利点です。

`map` の数字例をもう一度だけ。

```racket
(map double (list 1 2 3 4))
;; => (list 2 4 6 8)
```

リストを手で `(list (double 1) (double 2) …)` と書かずに済むのと同じで、色のリストに `colored-poly-60-6` を `map` すれば、虹色の六角形の部品列が一度にできます。**データの並びを変えれば、絵のバリエーションが変わる**——これが高階関数の実用的な面白さです。

（ISL では渡す関数に必ず名前を付けます。`lambda` でその場に書くのは ISL+ の話で、今版では扱いません。）

---

#### 終.4 グラフィックスでも、高階関数と関数の合成が実験になる

タートルグラフィックスは、「画面に線を引く手続き」に見えますが、中身は **CommandList というデータの組み立て** です。だからこそ、リスト処理の高階関数がそのまま絵の実験につながります。

試してみると面白い方向の例です（今版の道具の延長で足ります）。

- **パラメータを変える** … `spiral-loop-90` の歩数や、長さの式 `(+ 5 (* i 2))` の係数だけ変えて模様の密度を見る  
- **部品関数を差し替える** … `map` に渡す関数を「六角形」から「正方形」に変えるだけで、同じ色リストから別の並びが生まれる  
- **命令列を合成する** … `(append 背景の命令 本体の命令)` や `(list (change-bg-color "black") …)` のように、小さなたたき台をくっつけて一枚の絵にする  
- **ずらして重ねる** … 付属コードの `shift-then` / `row-of-squares` のように、「移動の前置き」＋「図形」を関数で合成する  

ここでいう「関数の合成」は、難しい圏論の話ではなく、**小さな CommandList を返す関数どうしを `append` や `list` でつなぎ、大きな図を作る** という実務的な意味です。手続きを長い一本道で書く代わりに、部品を組み合わせて試行錯誤できる——グラフィックスは、その効果が目に見えるので学習に向いています。

---

#### 終.5 おわりに

最初は括弧が多くてとっつきにくく見えたかもしれません。慣れてくると、「同じことのくり返し」と「回ごとに変わるくり返し」の書き分けや、`map` / `build-list` に関数を渡す感覚が少しずつ読み取れるようになります。

「プログラムで図を描き、図でプログラムの型紙を確かめる」。  
本書で触れた高階関数と畳み込みの考え方は、この先にアニメーションやシミュレーションへ進むときにも、同じ骨格で役立ちます。色々な係数や部品関数を差し替えて、自分だけの模様を試してみてください。
