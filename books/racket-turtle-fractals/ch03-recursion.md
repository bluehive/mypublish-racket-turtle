#### 3.0 なぜ「再帰」が必要なのか？

##### 🪆 マトリョーシカ人形と鏡の中の自分
「**再帰（さいき / Recursion）**」という言葉を聞いたことがありますか？

ロシアの伝統工芸品 **マトリョーシカ人形** を思い浮かべてみてください。大きな人形のパカッと蓋を開けると、中から一回り小さな人形が出てきます。その小さな人形の蓋をまた開けると、さらに小さな人形が出てきます。最後に一番小さな「これ以上開かない人形」にたどり着いて終わりになります。

このように、**「全体と同じ仕組みが、内部に小さくなって繰り返し入っている構造」** をプログラミングで表現するのが **再帰** です。

##### 🐱 Scratch の「繰り返し」と「再帰」の違い
第2章で使った `repeat`（繰り返し）は、「同じ動きをそのまま回数分繰り返す」のには便利でした。

しかし、次のような図形を描きたいときはどうでしょう？
- 1周進むごとに、**前進する距離が少しずつ長くなる螺旋（渦巻き）**
- 1段階進むごとに、**枝が半分に小さくなって2本に増える木**

Scratch の `[ (10) 回繰り返す ]` ブロックでは、「毎回長さが変わる」「分岐して2本に増える」といった複雑な変化を表現しようとすると、変数が増えすぎて頭がパニックになってしまいます。

Racket の **再帰** を使えば、**「自分自身を呼び出す」** というたった数行のコードを書くだけで、どんなに複雑な変化や拡大・縮小も完璧に表現できるようになります！

#### 3.1 再帰を支える2つの絶対ルール

再帰プログラムを書くときは、必ず次の **2つの約束（ルール）** を守る必要があります。

```text
               ┌── 1. 基底条件 (Base case) : 「ここで止まれ！」という終了条件
  再帰のルール ┤
               └── 2. 再帰ステップ (Recursive step) : 問題を少し小さくして自分を呼ぶ
```

1. **基底条件（Base Case）**: 「これ以上小さくならない最小の状態（停止条件）」。マトリョーシカの一番小さな人形にあたります。これがないと、プログラムは永久に止まらずフリーズしてしまいます（無限ループ）。
2. **再帰ステップ（Recursive Step）**: 「問題を1段階だけ小さくして、自分自身（関数）を呼び出すステップ」。

##### ✍️ 再帰関数を「自分で書く」5ステップ

再帰は「完成品を眺める」より「型紙に沿って埋める」と手が動きます。次の**5ステップ**で、白紙から組み立ててみましょう。

**例題**: 「残り回数 `n` だけ、長さ `len` で前進して右に90度回る」関数 `steps` を作ります。

**ステップ1: 何を返すか決める** → `CommandList`（命令のリスト）

**ステップ2: いつ止まるか（基底条件）を先に書く** → まず「止まる枝」だけ書きます:

```racket
(define (steps n len)
  (cond
    [(<= n 0) empty]   ; ← まずここだけ書く
    [else ...]))       ; 中身はまだ空っぽ
```

**ステップ3: 「今の1回分」を書く** → 前進して右に90度:

```racket
(list (forward len) (turn-right 90))
```

**ステップ4: 「残り」を小さくして自分を呼ぶ** → `n` を 1 減らす:

```racket
(steps (sub1 n) len)
```

**ステップ5: `append` でつなぐ** → 「今の1回分」と「残りの命令リスト」を連結:

```racket
(define (steps n len)
  (cond
    [(<= n 0) empty]
    [else (append (list (forward len) (turn-right 90))
                  (steps (sub1 n) len))]))
```

**できあがりをチェック**: `(steps 0 10)` → `empty`（何もない）/ `(steps 1 10)` → 前進1回だけ / `(steps 4 10)` → 正方形！ この順で `check-expect` を書けば、組み立てた関数が正しいか機械に確認させられます。

##### 🌀 徐々に大きくなる螺旋（Spiral）を描いてみよう
「1歩進んで左に曲がる。次は少し長さを伸ばして前進する」を繰り返す螺旋関数を作ってみましょう。

```racket
#lang racket
(require teachpacks/racket-turtle)

;; spiral: 回転角 a, 現在の長さ x, 残りステップ times -> CommandList
(define (spiral a x times)
  (cond
    [(<= times 0) empty]   ; 1. 基底条件: 残り回数が 0 以下なら空のリストを返して終了！
    [else
     (append (list (forward x) (turn-left a))             ; 今の1ステップを描く
             (spiral a (+ x 2) (sub1 times)))]))          ; 2. 再帰ステップ: 長さ x+2, 回数 times-1 で自分を呼ぶ！

;; 🖥️ DrRacket で画面に描画して確かめる呼び出し例
(draw (spiral 90 5 40))
```

- `(sub1 times)` は `times - 1` の意味です。
- 呼び出されるたびに `times` が 1 ずつ減っていくので、いつか必ず `(<= times 0)` の基底条件に引っかかり、計算が安全にストップします。

##### 🧮 手計算してみよう（times がどう減るか）

`(spiral 90 5 3)` を手で追いかけてみましょう。「forward を描く」のは何回になるでしょうか？

| 呼び出し | times | 描く長さ x | まだ続く? |
|---|---|---|---|
| 1回目 | 3 | 5 | はい（あと2） |
| 2回目 | 2 | 7 | はい（あと1） |
| 3回目 | 1 | 9 | はい（あと0） |
| — | 0 | — | **基底条件: `empty` で終了** |

→ `forward` はちょうど **3回**。`times` の値と同じ回数ですね。コードの `(<= times 0)` は「残り回数が 0 になったら終わり」なので、**times 回だけ forward する**、と覚えておきましょう。

（注意: 途中で `x` は 2 ずつ大きくなっているので、1回目は長さ 5、2回目は 7、3回目は 9 の線が描かれます。**長さが変わりながら回数をこなす**のが、`repeat` では書きにくい再帰の良さです。）

#### 3.2 2つの主要な再帰テンプレート（型紙）

How to Design Programs (HtDP) の教えでは、再帰のコードは勘で書くのではなく、**データの形に合わせた「テンプレート（型紙）」** を使って機械的に組み立てます。

##### 📄 パターンA: 自然数（深さ・カウントダウン）の再帰
「残り深さ `depth`」や「残り回数 `times`」といった数値を 1 ずつ減らしながら繰り返す型紙です。

```racket
(define (depth-temp d)
  (cond
    [(<= d 0) (...)]                       ; 基底条件 (0 以下なら止まる)
    [else (... d (depth-temp (sub1 d)))])) ; 再帰ステップ (d を 1 減らして自分を呼ぶ)
```

###### 🧮 階乗（Factorial: $n!$）の例
数学の階乗 $n! = n \times (n-1) \times \dots \times 1$ も、この型紙で美しく書けます。

```racket
(define (factorial n)
  (cond
    [(zero? n) 1]                           ; 0! = 1 (基底)
    [else (* n (factorial (sub1 n)))]))     ; n * (n-1)! (再帰)
```

##### 📄 パターンB: リストの構造的再帰 —「含まれているか？」を判定する

リストの先頭 `(first lst)` を1つ処理し、残りのリスト `(rest lst)` を再帰に渡す型紙です。ここでは、HtDP の定番例「**リストに特定の名前が含まれているかを判定する関数**」を、設計レシピに沿って一から組み立ててみましょう。

**設計課題（Sample Problem）** あなたは新しい携帯電話の連絡先リストの開発に取り組んでいます。携帯電話の所有者は、さまざまな機会にこのリストを更新し、参照します。差し当たり、あなたはこの連絡先リストを受け取り、その中に `"Flatt"` という名前が含まれているかどうかを判定する関数を設計するタスクを割り当てられました。

（※ここでは「友人（friend）」という言葉を、現実世界ではなくソーシャルネットワークの意味で使用しています。）

この課題の解決策が得られたら、リスト内の**任意の名前**にマッチする一般的な関数へと一般化します。まず、関数が検索する名前のリストを表現するデータ定義 **List-of-names** を用意しましょう。それは「空リスト `empty`」か、「文字列を先頭に持ち、残りも List-of-names である cons リスト」のどちらかです。

次に、**ヘッダー（シグネチャ、目的、スタブ）** を作成します。

```racket
;; List-of-names -> Boolean
;; リストに "Flatt" が含まれているかを判定する
(define (contains-flatt? alon)
  #false)
```

関数が受け取る名前のリストを表す引数名として、`a-list-of-names` は良い名前ですが、少し長くて煩雑なため、短く `alon` と略します。

**例（テスト）を作る** 一般的な設計レシピに従い、次に関数の目的を説明する例を作成します。まず、最も単純な入力に対する出力を決定します。それは `'()` です。このリストには文字列が一つも含まれていないため、確実に "Flatt" も含まれていません。

```racket
(check-expect (contains-flatt? '()) #false)
```

次に、要素が1つだけのリストを考えます。以下は2つの例です。

```racket
(check-expect (contains-flatt? (cons "Findler" '())) #false)
(check-expect (contains-flatt? (cons "Flatt" '())) #true)
```

最初のケースでは、リストの唯一の項目が "Flatt" ではないため、答えは `#false` です。2番目のケースでは、唯一の項目が "Flatt" であるため、答えは `#true` です。最後に、より一般的な例を示します。

```racket
(check-expect (contains-flatt? (cons "A" (cons "Flatt" (cons "C" '())))) #true)
```

やはり、リストに "Flatt" が含まれているため、答えは `#true` になるはずです。**立ち止まって、答えが `#false` にならなければならない一般的な例を自分でも作ってみてください。**

一息ついて、プログラムを実行してみましょう。ヘッダーは関数の「ダミー（スタブ）」定義であり、いくつかの例があり、それらはテストに変換されています。最も良いことに、そのうちのいくつかは実際に成功します。**誤った理由で**成功しているのですが、成功することには変わりありません（スタブは常に `#false` を返すので、`#false` を期待するテストが「偶然」通ってしまうのです）。ここまで理解できたら、先を読み進めましょう。

**テンプレートを設計する** 第4のステップは、データ定義に一致する関数テンプレートを設計することです。文字列リストのデータ定義には2つの節があるため、関数の本体は2つの節を持つ `cond` 式でなければなりません。2つの条件によって、関数が受け取ったのがどちらの種類のリストであるかを判定します。

```racket
(define (contains-flatt? alon)
  (cond
    [(empty? alon) ...]
    [(cons? alon) ...]))
```

2番目の節では、`(cons? alon)` の代わりに `else` を使用することもできます。

**テンプレートを仕上げる** あとは2つの節を埋めるだけです。空リストなら答えは `#false`。cons のリストなら「先頭が "Flatt" なら `#true`」「そうでなければ残りのリストを再帰で調べる」の2択です。

```racket
(define (contains-flatt? alon)
  (cond
    [(empty? alon) #false]
    [else (or (string=? (first alon) "Flatt")
              (contains-flatt? (rest alon)))]))
```

これで4つのテストすべてが**本当の理由で**成功します。`(first alon)` で先頭を1つ調べ、`(rest alon)` で残りを自分自身に渡す——これが「リストの構造的再帰」の基本形です。

> 💡 **練習**: `contains-flatt?` を一般化して、任意の名前を受け取る関数に書き換えてみましょう。ヒント: 引数が1つ増え、`string=?` の比較相手が `"Flatt"` から引数に変わります。できたら `(contains? (list "A" "Flatt" "C") "Flatt")` が `#true` になることを確かめてみてください。

#### 3.3 タートル描画と再帰の組み合わせパターン

タートルグラフィックスで再帰を使うとき、よく使うパターンは次の3つです。

##### パターン1: `append` で命令をつなぎ合わせていく
直前の `spiral` のように、`append` を使って「今の1ステップの命令」と「残りの再帰で生成される命令リスト」を繋ぎ合わせます。

##### パターン2: 命令をパーツ化して `cons` でリスト化する
1ステップ分の装飾（ペンの太さ変更など）を別関数に切り出し、リストのネストとして組み立てる方法です。

```racket
(define (side-step x w a)
  (list (change-pen-size w)
        (forward x)
        (turn-left a)))

(define (spiral2 x w a times)
  (cond
    [(<= times 0) empty]
    [else (cons (side-step x w a)
                (spiral2 (+ x 4) (+ w 1) a (sub1 times)))]))

;; 🖥️ DrRacket で画面に描画して確かめる呼び出し例
(draw (spiral2 1 1 91 50))
```

#### 3.4 まとめと確認

再帰の考え方はマスターできましたか？
ポイントは以下の3点です。

1. **基底条件（止まる条件）** を最初に書く。
2. **再帰ステップ** で問題を1段階小さくして自分を呼ぶ。
3. リストや描画命令は `append` や `cons` で繋ぎ合わせる。

```bash
racket code/ch03-recursion.rkt
```
