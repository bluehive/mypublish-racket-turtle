#### 0.1 線を手で描くところから、プログラムで自動化する楽しさへ

##### ✏️ 正方形を「手順どおり」に描くと……
紙に正方形を描くとき、頭の中ではだいたいこんな指示を出しています。

1. まっすぐ線を引く  
2. 角で 90 度曲がる  
3. またまっすぐ線を引く  
4. ……これを **4 回** くり返す  

画面上のカメ（タートル）に同じことをさせると、命令はだいたいこう並びます。

```racket
(forward 100)   ; 100 進む
(turn-left 90)  ; 左に 90 度
(forward 100)
(turn-left 90)
(forward 100)
(turn-left 90)
(forward 100)
(turn-left 90)
```

1 本の線・1 回の曲がりは単純です。でも、正六角形・正十二角形・星・同じ図形をずらして並べる……と欲が出ると、**同じような行を何度も書き写す**ことになります。手作業のコピー＆ペーストは、すぐ長くなり、直し損ねも増えます。

##### 🤖 そこがプログラムの出番
プログラミングの楽しさのひとつは、この「手続き的に線分を描く処理」を、**短いルールにまとめてコンピュータに繰り返させる**ことにあります。

- 「進んで曲がる」を **1 セット** にする  
- それを **n 回** くり返す（第2章の `repeat`、第3章のリスト生成など）  
- 色や長さだけ変えて、同じ型紙で別の図形を量産する  

手で 20 行書いていた作業が、関数と繰り返しに変わると、「形のルール」だけに集中できるようになります。本書の今版は、この **自動化の第一歩** までを目標にします。

##### 🐱 Scratch を使ったことがある人へ
Scratch で `[○ 歩動かす]` や `[○ 度回す]`、`[○ 回繰り返す]` を並べた経験があれば、その感覚はそのまま使えます。違うのは、ブロックの枠が Racket では括弧 `( )` になること（次節）と、あとから **文字のプログラムとして保存・再利用しやすい** ことです。

本書では画面上のカメを動かす **タートルグラフィックス**（`racket-turtle`）を使い、次の順で進めます。

1. **第1章**: 式・関数・リストのさわり（BSL）  
2. **第2章**: カメで正方形や多角形を描く（BSL + turtle）  
3. **第3章**: 繰り返し（ループ）で、もっと複雑な図形へ（ISL + turtle）  

「線を一本ずつ」から「ルールを書いて一気に描く」へ。その切り替わりを、一緒に楽しんでいきましょう。

#### 0.2 なぜ Racket か——ブロックから文字へ、構文より「論理」を学ぼう

##### 🧱 Scratch ブロックと Racket の括弧は同じもの！
Scratch などのブロック言語から、Python や C言語、Java などのテキスト（文字）言語に引っ越すとき、多くの人がつまずくポイントがあります。

- セミコロン `;` を押し忘れてエラーになる
- 中括弧 `{ }` やインデント（字下げ）のズレで動かない
- `public static void main(String[] args)` のような呪文の意味がわからない

プログラミングで本当に大切なのは、こうした「細かな文法のルール（作法）」ではなく、**「どういう順番で論理を組み立てるか」** という考え方そのものです。

本書で採用する **Racket（ラケット）** は、世界最高峰のプログラミング教育教科書 *How to Design Programs (HtDP)* のために開発された言語です。Racket の文法は、驚くほどシンプルで、基本的にたった1つのルールしかありません。

```racket
(演算子 引数1 引数2 …)
```

例えば、足し算ならこう書きます。
```racket
(+ 1 2)   ; 1 と 2 を足す。結果は 3
```

「括弧が多くて変だな？」と思いましたか？ 実は、Scratch のブロックと見比べてみてください。

- Scratch の `[ (1) + (2) ]` ブロック ──> Racket の `(+ 1 2)`
- Scratch の `[ (50) 歩動かす ]` ブロック ──> Racket の `(forward 50)`
- Scratch の `[ (90) 度回す ]` ブロック ──> Racket の `(turn-left 90)`

**Racket の括弧 `( )` は、Scratch の「ブロックの枠線」そのもの** なのです！  
開いて閉じる括弧の中に「やりたいこと（演算子）」と「データ（引数）」を並べるだけ。セミコロンも特殊な記号もいりません。だからこそ、文法エラーでイライラすることなく、純粋な「図形を描く論理」に集中できるのです。

#### 0.3 DrRacket と BSL／開発環境の見取り図

##### 🛠️ 開発環境 DrRacket を用意しよう
1. [Racket 公式サイト](https://download.racket-lang.org/) から環境に合ったインストーラをダウンロードしてインストールします。
2. アプリケーションから **DrRacket** を起動します。
3. **おすすめ設定**:
   - `Edit → Preferences`（Mac は `DrRacket → Preferences`）の `Editing` → `General Editing` で **Show line numbers（行番号を表示）** にチェックを入れます。

##### 🎓 学びのレベル分け（BSL と ISL）
DrRacket には初学者が安全に学べる「言語レベル」が用意されています。本書では以下のアプローチ（**言語方針 A**）をとります。

| 段階 | 使用する言語設定 | 何を学ぶか？ |
|---|---|---|
| **第1章** | `#lang htdp/bsl` (Beginning Student) | 式・関数・自動テスト・リストの基礎 |
| **第2章** | `#lang htdp/bsl` + `teachpacks/racket-turtle` | カメの基本図形 |
| **第3章** | `#lang htdp/isl` (Intermediate Student) + turtle | `repeat` / `build-list` / `map` で複雑な図形（再帰は使わない） |

※ `htdp/bsl` の **HtDP** は教科書 *How to Design Programs*、**BSL** は *Beginning Student Language*（初心者言語）の略です。

##### 💻 相互作用ウィンドウ（REPL）で遊んでみよう
DrRacket の画面は上下（または左右）に2つに分かれています。
- **定義ウィンドウ（上・左）**: プログラム全体をファイルとして書いて保存する場所
- **相互作用ウィンドウ（下・右 / REPL）**: 1行コードを入れるとすぐその場で計算結果を返してくれる実験場

相互作用ウィンドウ（REPL: Read-Eval-Print Loop）に、次のように打ち込んで Enter キーを押してみましょう。

```racket
(+ 2 4)
; => 6 が表示される！

(+ 2 4 (* 5 5) (- (+ 3 3) 2) 1)
; 内側の括弧から順番に計算されて => 36 が表示される！
```

###### 💡 初心者が最初にやってしまうエラーのパターン
- `((+ 3 4))` ── 外側の括弧の先頭に「演算子」がないため、Racket が「何をすればいいの？」と混乱します。
- `(3 (+ 1 6))` ── `3` は数字であって命令（演算子）ではないためエラーになります。

**「括弧 `(` の直後には、必ず実行したい命令（関数や演算子）を書く」**。これだけを覚えておけば完璧です！
